# ADR

*Architecture Decision Records* registram uma decisão, o contexto que a tornou necessária e as consequências aceitas. O objetivo não é burocracia: é impedir que decisões pareçam arbitrárias meses depois.

## Quando criar

Crie um ADR para escolhas de alto impacto ou difícil reversão. Não crie para detalhe trivial de implementação. Mantenha o status atualizado quando uma decisão for substituída.

## Como usar

1. Descreva o problema e as alternativas reais.
2. Declare a decisão e o motivo da escolha.
3. Registre efeitos positivos, custos, riscos e módulos impactados.
4. Conecte a mudança de código e o mapa em [[Architecture Overview]].
